(S)MPC & An Uncertain Calculus

2019-07-23 · on the site · source

Abstract: Towards a minimal language for multi-party communication and computations. I (we?) define two new languages: \(\lambda_\div\), a language for probabilistic computation, and \(\lambda_o\) a language for multi-party secure computation.

\[\lambda_o\] is an extension of \(\lambda_\div\), however it doesn’t need to export the idea of a \(\div\) flipping primitive.

§Secure Two Party Communication (S2PC)

Generally, both parties will have an input to a function \(\lambda_o\), here we’ll call \(\textcolor{blue} A\)’s input \(\textcolor{blue} x\) and \(\textcolor{red} B\)’s input \(\textcolor{red} y\). Before either party can pass their inputs to \(\lambda_o\) they must create an authentication context with \(\bullet \ e\).

\[ (\lambda_o \ \textcolor{blue}{x} \ \textcolor{red}{y} \ . e) \ \textcolor{blue}{\bullet}a \ \textcolor{red}{\bullet}b \rightarrow e[a/\textcolor{blue} x,b/\textcolor{red} y] \]

We have up to three possible implementations for \(e\): \(e\), \(\textcolor{blue}{\bullet \ e}\) and \(\textcolor{red}{\bullet \ e}\). This allows for each party to perform arbitrary computations on the oblivious data, or to fix the garbling up front so no one party controls it. For example here the expression \(e\) was garbled by \(\textcolor{blue}A\).

\[ (\lambda_o \ \textcolor{blue}{x} \ \textcolor{red}{y} \ . \textcolor{blue}{\bullet}\ e) \ \textcolor{blue}{\bullet}a \ \textcolor{red}{\bullet}b \rightarrow \textcolor{blue}{\bullet \ e[\textcolor{black}a/\textcolor{blue}x,\textcolor{black}b/\textcolor{red}y]} \]

Traditional function notation can be colored to indicate the same notion.

\[ \textcolor{blue}{\bullet} \ f \ \textcolor{blue}x \ \textcolor{red}y = \textcolor{blue}{f(x,\textcolor{red} y)} \\ \textcolor{red}{\bullet} g \ \textcolor{blue}x \ \textcolor{red}y = \textcolor{red}{g(\textcolor{blue}x,y)} \]

We see that each party, \(\textcolor{blue} A\) and \(\textcolor{red} B\), have unique functions, \(\textcolor{blue} f\) and \(\textcolor{red} g\) respectively. However it is also possible to define \(e = \textcolor{blue}{f} \cup \textcolor{red}{g}\). These functions are oblivious to the other party’s data but follow consistent use.

One example pair of \(\textcolor{blue} f\) and \(\textcolor{red} g\) functions is a classic problem of Oblivious Transfer (OT). In this case, \(\textcolor{blue} A\) wants to access a specific element from \(\textcolor{red} B\)’s database, without \(\textcolor{red} B\) knowing what element was retrieved. For this example, we’ll use a database projection function \(\textcolor{red}{p}\) (oblivious to anything else about the database), which takes an oblivious index \(\textcolor{blue} i\).

\[ \Gamma \vdash \lambda_o \ \textcolor{blue}{i} \ \textcolor{red}{p} \ . \textcolor{red}{p} \ \textcolor{blue}{i} : \sigma_o \rightarrow (\sigma_o \rightarrow \tau_o) \rightarrow \tau_o \\ \cong \\ \Gamma \vdash \lambda_o \ \textcolor{blue}{i} \ \textcolor{red}{p} \ . \textcolor{red}{p} \ \textcolor{blue}{i} : \sigma_o \times (\sigma_o \times \tau_o) \rightarrow \tau_o \]

Or as a solution to Yao’s Millionare Problem:

\[ \Gamma, >: \mathbb{Z} \times \mathbb{Z} \rightarrow \{0,1\} \ \vdash (\lambda_o \ \textcolor{blue}a \ \textcolor{red}b \ . \textcolor{blue}a > \textcolor{red}b) \]

It’s worth noting that the \(>\) operator in the figure above is written in black because it’s “baked in” to the protocol.

§S3PC

This notion expands naturally for a third member of the computation, Carrol (\(\textcolor{green} C\)). Similar to the S2PC case above, we can define a \(\lambda_o\), which now takes three arguments and tells each member what position in line they are in a group.

\[ \lambda_o \ \textcolor{blue}{x} \ \textcolor{red}{y} \ \textcolor{green}{z} \ . \\ \textcolor{blue}{place(x, \left\{x,\textcolor{red}y,\textcolor{green}z\}\right)} \\ \textcolor{red}{place(y, \left\{\textcolor{blue}x,y,\textcolor{green}z\}\right)} \\ \textcolor{green}{place(z, \left\{\textcolor{blue}x,\textcolor{red}y,z\}\right)} \]

§\(\lambda_\div\) the Uncertainty Calculus

\[ \div \ a \\ 50\% \rightarrow a \\ 50\% \rightarrow \_ \]

\[ \div \div a \\ 25\% \rightarrow a \\ 75\% \rightarrow \_ \]

\[ \div \ a \ b \\ 50\% \rightarrow a \ b \\ 50\% \rightarrow b \ a \]

\[ a \div b \\ \div \div \ a \ b \\ 50\% \rightarrow a \ b \\ 50\% \rightarrow b \ a \]

Below the order of operations \(f \ g\) is certain, while the order of \(a \ b\) is uncertain.

\[ \lambda f \ g \ a \ b . f \ g \div a \ b \\ \]

Full expressions can be wrapped and made uncertain.

\[ \lambda \_ . \div \ (\lambda a \ b . a \ b) \ (\lambda a \ b . b \ a) \]

Much more work is clearly needed on this idea…
